## 1. 项目目标

RASP5 的目标不是单纯把旧版 VB.NET RASP 翻译成 Python，而是在尽量保留旧版核心工作流和输出习惯的基础上，形成一个更可维护、更可验证、能扩展到空间数据/GIS 工作流的新版本。

当前主线目标分为两层：

1. 复刻和稳定旧版 RASP 的核心分析方法：DIVA、S-DIVA、DEC、S-DEC、BioGeoBEARS、S-BioGeoBEARS、BayArea、BBM，以及性状重建相关的 BayesTraits / ape / phytools。
2. 在此基础上补齐高分文献常用的空间结果链路：BSM 事件表、事件 through time、区域迁移网络、source-sink summary、time-slice map、GIS-ready export。

## 2. 当前判断

`二次优化版.xlsx` 的路线结构可以采用，但需要按“子任务”执行，而不是按整个 F 功能一次性实现。

核心原则：

- `F ID` 是稳定功能编号，不代表阶段。
- `Phase` 绑定到子任务，例如 `F13a/F13b/F13c`，而不是绑定整个 `F13`。
- Phase 0 只收敛现有 BGB/BioGeoBEARS/BSM 结果可信度，不做复杂地图。
- Phase 1 才做空间中间层：area mapping、occurrence、polygon、coordinate-to-area。
- Phase 2 做论文型空间结果：event-through-time、迁移网络、time-slice map、GIS export。
- Phase 3 做高级诊断：branch probability、posterior/tree-set event aggregation、树-表-地图联动。

## 3. 文献证据如何使用

Excel 中的 40 篇文献和标准来源不应被直接翻译为功能列表，而应作为功能优先级和图形模式的证据。

已形成的主要结论：

1. 高影响生物地理论文很少展示“整棵树所有枝上多状态概率曲线”。它们更常把 BSM / ancestral range 结果压缩成事件表、时间曲线、区域迁移箭头、source-sink 矩阵、time-slice maps。
2. RASP5 的短板不是“不会画一个漂亮树图”，而是缺少“离散区域代码 A/B/C/D 与真实地图对象 polygon/centroid/occurrence”的中间层。
3. BSM 事件是后续空间分析的核心数据源，但 Phase 0 只应做事件表浏览和审计，不应提前做地图联动。
4. 古地图、GPlates、栅格环境层、复杂生态解释属于后期扩展，不应阻塞 Phase 0 到 Phase 2。

文献证据对应的功能方向：

- BSM 事件统计和迁移网络：Kawahara 2023、Doré 2025、Brocklehurst 2018、Cole 2022 等。
- event-through-time / MDisE / MDivE / breakpoint：Zhang 2023、Klaus 2016、Brocklehurst 2018 等。
- source-sink / focal area assembly：Antonelli 2018、Zhang 2023 等。
- 空间数据层和区域化：Holt 2013、Liu 2023、GeoJSON RFC 7946、OGC GeoPackage、GDAL/OGR。
- 古地理和环境层：Leprieur 2016、Skeels 2023、GPlates/PALEOMAP/GDAL 等，暂列 Deferred。

## 11. UI 和架构约束

### 11.1 普通结果与 BSM 结果分离

普通树图结果：

- 节点祖先范围概率
- List
- Information
- Time
- CSV export

BSM event browser：

- Raw ana/clado event table
- event filters
- Summary
- Time summary
- CSV export

不得再把 BSM raw event table 塞回普通结果树图窗口。

### 11.2 地图功能不得提前阻塞 Phase 0

没有 area mapping / polygon / centroid 时：

- 不允许地图箭头。
- 不允许 time-slice map。
- 可以显示 raw event table 和非空间 summary。

### 11.3 运行前检查应统一

后续不应让每个分析方法各自弹出不一致错误。应建立统一 preflight report：

- Blocker：必须修复，否则不能运行。
- Warning：可以运行，但结果解释有风险。
- Info：提示功能可用性或数据限制。

### 11.4 测试产物管理

开发阶段可保留最近 5 天 runs 产物用于追溯；Phase 0 checkpoint 前应明确：

- 哪些 runs 可删除。
- 哪些结果作为 benchmark 保留。
- engine 目录不得残留运行垃圾。
