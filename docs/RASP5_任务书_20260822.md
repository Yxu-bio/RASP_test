## 1. 项目开发历程与关键决策

### 1.1 从界面复刻转向算法工作流复刻

项目最初目标是复刻旧版 RASP 的全部功能，但很快确认：真正需要复刻的是输入、配置、引擎调用、统计语义和输出工作流，而不是把 VB.NET 逐行翻译为 Python。

因此形成了当前基本架构：

```text
GUI
  -> config model
  -> analysis service
  -> external engine runner
  -> raw output parser
  -> normalized result
  -> tree/table/map renderer and exporter
```

Python 不重新实现 DIVA、DEC、BioGeoBEARS、BayArea、MrBayes 或 BayesTraits 的核心算法，只负责可靠编排和展示。

### 1.2 S-DIVA 的第一次核心纠偏

早期 Python 版逐棵调用 DIVA 后自行汇总，结果与旧版 RASP 明显不一致。调查旧源码后确认，旧版 S-DIVA 使用修改版 `DIVA.exe` 的 config/proc 工作流完成统计。

已完成：

- 改为由修改版 DIVA 引擎承担 S-DIVA 统计；
- 对齐随机树抽样、Final tree、Fossil、Include/Exclude、Threads；
- 对齐默认 keep、Random Step、Save/Load Setting；
- 修复卡死、Fossil 约束和节点映射问题。

这一阶段确立了后续原则：**先确认原版真实逻辑，再决定对齐旧版还是采用新引擎的合理语义。**

### 1.3 DEC/S-DEC 转向 lagrange-ng 原生语义

旧版 RASP 使用的修改版 Lagrange 支持 `includedists/excludedists`，当前项目使用 `lagrange-ng.exe`。两者不是简单语法替换。

已完成：

- DEC 与 S-DEC 使用 lagrange-ng 原生配置；
- 支持 Maximum areas、period area rules、dispersal constraints、Fossil/MRCA；
- 修复 root age/tree scaling；
- S-DEC 使用外层 Threads 并行多棵树，每个子进程固定 OpenBLAS 单线程；
- 移除旧 Lagrange 兼容执行分支，不再假装 post-parse 过滤等价于旧算法。

### 1.4 lagrange-ng 上游问题修复

实测发现上游源码在 `evaluate` 模式中读入固定 dispersion/extinction 后，计算路径仍可能使用默认 `0.01`；period d/e parser/fallback 也不完整。

已完成：

- 查明源码数据流；
- 修复固定 d/e 和 period d/e 接线；
- 重新编译 Windows 引擎；
- 保留补丁和使用说明；
- 当前 RASP 已接入修复版引擎。

### 1.5 BioGeoBEARS 主链与 BSM 分离

已完成 BGB、S-BGB 和六模型检测：

- DEC、DEC+J、DIVALIKE、DIVALIKE+J、BAYAREALIKE、BAYAREALIKE+J；
- null range 与 DEC* 的合理处理；
- +J 模型先运行对应无 +J 模型，再传递 d/e 初值；
- batch runner 减少重复加载 R/BioGeoBEARS；
- S-BGB 使用旧版 clade 完全匹配式合并；
- model test 输出 AIC、AICc、weights、LRT/teststable。

BSM 曾被错误地嵌入普通结果树并覆盖树图。随后已明确分离：

- 普通 BGB 结果只展示节点祖先状态；
- BSM 由独立入口生成或载入；
- BSM 事件表和网络分析使用随机映射事件，不污染普通结果树。

### 1.6 BayArea 与 BBM

BayArea 已从旧版未知 DLL 转为重新编译的 BayArea 1.0.3 exe runner，并实现坐标、MCMC、Tracer、burn-in、seed、多链和原始结果保存。期间修复了 `distancePowerPrior` 表面传入但计算硬编码的问题，以及相关初始化/迭代器问题。

当前结论：

- `DISTANCE_NORM` 为 Beta/release candidate；
- `INDEPENDENCE` 仅保留兼容入口，并明确不推荐；
- 已完成 Psychotria `4 x 5,000,000` cycles 独立链收敛基准，固定输入、引擎 hash、种子、1M/2.5M/5M 检查点、split-Rhat、每链 ESS、标准化半链漂移和节点后验跨链一致性均可重复；
- 已补齐 GUI 长链、burn-in、Tracer 判读、失败处理和结果留存教程。当前只剩最终安装包上的外部用户复现，不再是 BayArea 功能缺口。

BBM 已通过 MrBayes 接入，支持节点选择、OG0 advanced、进度/取消、结果解析和树图。旧 `BAYESDLL.dll` 不再作为默认主链。Psychotria 系统对照已证明：当前与旧版 Large dataset 路径使用的 MrBayes 二进制 SHA-256 相同；固定 seed 下，当前显式 `TID` 约束与旧数字 taxon 约束的原始两条 run 和合并边际概率均为 0 差异。当前全精度范围概率相对旧版 `Single/F6` 流水线的最大差为 `0.0001483944` 个百分点。生产 parser 会拒绝截断样本，只输出用户选择的节点；默认链数由旧版 10 改为无已知 allocation warning 的 4。证据见 `docs/bbm_legacy_case_latest.md`。

### 1.9 大树与 Lineage Range Dynamics

1534-tip 数据暴露了 ETE3 vendor 版在矩形树、环形树、tip 标签、节点位置和窗口尺寸上的问题。近期已增加：

- 大树矩形/环形渲染适配；
- tip 状态与标签位置修正；
- 多个对话框可调整大小/最大化；
- 代表性窗口行为检查；
- 专门的大树渲染检查工具。

`Lineage Range Dynamics` prototype 已实现 node interpolation、BGB endpoints、BSM summary/single-map、树图与地图联动。它与旧任务书删除的“全树枝-时间多状态概率曲线场”存在边界冲突，且当前产品价值与科学语义不足以支持公开发布。

本任务书重新定义：

- 原先声称“任意枝任意时间的祖先分布后验概率场”的功能仍为 Removed；
- 当前 `Lineage Range Dynamics` 状态为 **Sealed prototype**，结果窗口不显示入口，主窗口不向其注入运行上下文；
- node interpolation 只能解释为节点状态之间的展示插值，不能解释为真实枝内历史；
- BSM 模式必须明确区分 summary 与 single stochastic map；
- 底层代码和专项检查暂时保留，后续只有完成独立产品重设计后才能重新启用；开发记录见 `docs/lineage_range_dynamics/README.md`。

## 2. 产品边界与结果语义

### 2.1 产品定位

RASP5 是一个面向历史生物地理与祖先性状分析的可审计桌面工作台。它连接树、树集合、范围/性状矩阵、occurrence、GeoJSON、成熟外部引擎、标准化祖先结果、BSM 事件和可复现导出。

RASP5 不是：

- 第三方算法的 Python 重写集合；
- 所有旧版 bug 的逐字符复制；
- 当前 Rust BioGeoBEARS 重写的 GUI 外壳；
- 已经提出新祖先分布统计模型的软件；
- 为了“功能多”而持续增加顶层菜单的工具箱。

### 2.2 三条必须分离的结果语义

1. **祖先节点状态**：DIVA、DEC、BioGeoBEARS、BayArea、BBM 等输出的节点范围或概率。
2. **启发式事件摘要**：普通结果窗口 Information/Time 根据节点最优状态推断的 dispersal/vicariance/extinction，不是后验随机历史。
3. **BSM 随机映射事件**：来自 BioGeoBEARS stochastic maps 的 `ana.events` / `clado.events`，可用于事件频率、时间和迁移网络统计。

`Lineage Range Dynamics` 还必须额外区分：

- node interpolation：展示插值；
- BGB endpoints：模型端点结果之间的展示；
- BSM summary：多条随机历史的汇总；
- single BSM map：一条抽样历史，不代表确定历史。

### 2.3 旧版兼容原则

| 类型 | 处理原则 |
| --- | --- |
| 算法逻辑 | 优先查旧源码、旧输入和原始输出，确认后对齐 |
| 新引擎语义 | 旧功能不能原生映射时按新引擎重新设计，不伪造等价性 |
| UI 工作流 | 在不误导算法含义时保持旧用户熟悉的操作方式 |
| 显示约定 | 可以兼容，但必须与实际状态空间分开 |
| 已确认旧 bug | 不复刻，记录差异和理由 |

## 7. 工程实施原则

本项目不采用“为了防止一切可能错误”而层层加 fallback 的方式。只在真实边界和已观察回归处做检查。

### 7.1 必须坚持

1. 每个参数只有一个权威来源：GUI 生成 config，service/runner 不再保留重复隐藏入口参数。
2. 外部引擎失败时保留真实 command、config、stdout/stderr 和 run directory。
3. 不支持的模型语义直接禁用或明确标记，不做静默近似。
4. parser 只接受已知输出契约；格式变化应明确失败，不凭猜测拼出结果。
5. 每个真实 bug 增加一个能复现原问题的最小回归测试。
6. 测试使用固定 fixture，不依赖用户当前 `runs` 目录。

### 7.2 明确避免

- blanket `try/except` 后返回空结果；
- 多层自动重试和自动更换模型；
- “旧版失败就新引擎、再失败就 Python 近似”的兼容链；
- service 和 GUI 同时维护相同默认值；
- 为理论上所有异常组合编写大量不可触达分支；
- 用兜底归一化强行让结果接近旧版百分比。

最小验证标准：每个稳定引擎一套参数传播测试、一个固定数值金标准、一个真实工作流测试；每个有状态 GUI 一套针对已发生刷新回归的交互测试。

## 14. 任务书维护规则

1. 本文档是当前权威路线；旧任务书只保留历史决策。

3. 修复 bug 后更新对应测试或验证记录，不只保留聊天说明。

6. 不为理论上的所有异常增加防御层，只针对真实边界和已观察回归。
7. 不用 fallback 或后处理强行逼近旧版结果。
8. 论文目标不改变正确性、可复现性和诚实边界的优先级。
