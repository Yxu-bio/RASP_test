## 0. 执行摘要

RASP5 当前不是“核心功能还没接完”，而是“功能面已经足够宽，但尚未达到可发布证据标准”。现在的位置是 **M0 Development checkpoint**，下一目标是 **M1 Feature-complete Beta**。

| 方面 | 当前判断 | 下一步重点 |
| --- | --- | --- |
| 祖先分布重建 | 主链基本齐全，多数为 Stable candidate | 参数追踪、数值金标准、树集合有效样本审计 |
| 性状重建 | 方法入口较完整，整体仍为 Beta/Experimental 混合 | 收紧模型与结果边界，不再继续扩模型 |
| 空间数据 | occurrence 到 range matrix 的中间层已成形 | schema、复杂空间边界、真实数据回归 |
| BSM 事件与网络 | 已有可用的事件表、时间汇总和网络编辑链 | 统计语义、Dore 1000-map 对照、真正 Phase 2 测试 |
| 发布工程 | 有内部引擎包，但还不是正式软件制品 | clean checkpoint、README、许可、CI、installer |

当前总原则：**冻结新的顶层功能，先把已有功能变成可验证、可安装、可引用和可复现的版本。**

```text
M0 当前开发现场
  -> M1 功能完成 Beta：范围冻结 + 核心数值可信 + 真正自动检查
  -> M2 Release Candidate：干净安装 + 文档许可 + 发布门禁
  -> M3 Manuscript-ready：固定版本 + benchmark + 外部复现
  -> M4 Advanced research：新算法、新生物学故事和延期功能
```

## 1. 为什么重新定位

旧任务书把项目组织为一条线性的 `Phase 0 -> Phase 1 -> Phase 2 -> Phase 3` 空间功能路线。这个结构在 2026-06-16 当时是合理的，但已经不能准确描述当前项目：

1. 旧版 RASP 核心方法复刻已经从“补界面”推进到外部引擎调用、参数接线、树集合合并、节点映射和结果语义核对。
2. BayesTraits、ape、phytools、S-phytools 和连续性状可视化形成了独立的性状重建板块。
3. Spatial Data Manager、Region GeoJSON Builder、occurrence 编码和 taxon matching 已形成空间数据中间层。
4. BioGeoBEARS BSM 已从普通结果窗口分离，形成独立的事件表、时间汇总、迁移网络和地图编辑工作流。
5. lagrange-ng 和 BayArea 均发现了上游“参数表面读入但计算路径未使用”的真实问题，并完成源码修复、重编译和补丁记录。
6. 项目开始具备独立引擎包和可重复打包能力，发布工程已成为单独工作流。
7. 某些早期想法经过实测被主动删除，例如 Node Range Map 和枝-时间祖先分布概率场。继续保留在路线图中会误导开发。
8. 旧 F 编号与 Phase 对应关系割裂；一些功能同时跨越数据、计算、结果和地图，无法归入单一 Phase。

因此，新任务书不再用旧 Phase 编号表示完成顺序。项目改为：

- 用**功能成熟度**描述当前可信程度；
- 用**工作包（Work Package）**组织待办；
- 用**发布里程碑（Milestone）**决定何时可以进入下一阶段；
- 先形成可验证、可发布、可写论文的核心，再考虑高级扩展。

## 2. 项目新定位

### 2.1 一句话定位

RASP5 是一个面向历史生物地理与祖先性状分析的可审计桌面工作台：它把树、分布/性状矩阵、空间记录、成熟计算引擎、祖先状态结果和 BioGeoBEARS 随机映射事件连接成可检查、可复现、可导出的完整工作流。

### 2.2 RASP5 不是什么

RASP5 不是：

- VB.NET 到 Python 的逐行翻译；
- 用 Python 重新实现 DIVA、DEC、BioGeoBEARS 或 BayesTraits 算法；
- 对所有旧版行为无条件逐字符复制；
- 把所有生物地理与性状方法堆进同一界面的工具箱；
- 在当前主项目内重写 BioGeoBEARS 数值核心；
- 已经完成的新祖先分布统计模型。

### 2.3 当前可以主张的贡献

RASP5 可以主张：

1. **可信引擎编排**：Python 负责输入、参数、进程、日志、解析和展示，算法由对应成熟引擎承担。
2. **旧版行为审计**：区分旧版真实算法、界面行为、显示层约定和历史 bug，而不是盲目追百分比。
3. **参数可追溯**：持续核对 GUI 参数是否真正传入计算路径，并修复 lagrange-ng、BayArea 的实际接线问题。
4. **树集合工作流**：S-DIVA、S-DEC、S-BioGeoBEARS 采用与各自旧版逻辑相符的运行和合并策略，而不是共用一个 Python 汇总模板。
5. **空间数据中间层**：把 occurrence、polygon、area code、taxon name 和祖先分布矩阵建立成可保存、可审计的映射关系。
6. **BSM 事件综合**：从 BioGeoBEARS stochastic maps 生成可筛选事件表、时间汇总、source-destination 网络、地图与导出结果。
7. **性状重建集成**：通过 BayesTraits、ape 和 phytools 提供离散/连续性状重建及连续性状展示。
8. **大数据与可复现性**：支持大树、149k occurrence 级空间编码、1000-map BSM 案例和独立引擎包。

### 2.4 当前不能主张的内容

当前不能主张：

- RASP5 提出了新的 DEC/DIVA/BioGeoBEARS 概率模型；
- 所有方法与旧 RASP 在所有数据上数值完全一致；
- 所有 BayesTraits/phytools 模型都能输出节点祖先状态；
- BayArea `INDEPENDENCE` 已达到推荐的生产状态；
- Phase 2/3 所有空间高级功能均已完成；
- 当前仓库已经是可直接投稿或正式发布的软件制品。

## 3. 产品边界和数据流

### 3.1 五个产品层

```text
Input and QA
  Tree / tree set / matrix / occurrence / GeoJSON
            |
            v
Reconstruction adapters
  DIVA / lagrange-ng / BioGeoBEARS / BayArea / MrBayes
  BayesTraits / ape / phytools
            |
            v
Normalized results
  node states / probabilities / model fit / logs / provenance
            |
            v
Event and spatial synthesis
  BioGeoBEARS BSM events / time bins / dispersal network / map
            |
            v
Presentation and export
  tree view / tables / figures / CSV / GeoJSON / reproducible bundle
```

### 3.2 三条必须分开的结果语义

1. **祖先节点状态**：DIVA、DEC、BioGeoBEARS、BayArea、BBM 等产生的节点范围或状态概率。
2. **启发式事件摘要**：普通 DIVA/DEC/BGB 结果窗口的 Information/Time，根据节点最优状态推断 dispersal/vicariance/extinction；不是随机映射后验事件。
3. **BSM 随机映射事件**：只来自 BioGeoBEARS BSM 的 `ana.events` / `clado.events`，可用于事件频率、时间和迁移网络统计。

三者不得在数据结构、界面标题、论文方法或解释中混用。

### 3.3 旧版兼容原则

旧版对齐分为四类：

| 类型 | 处理原则 |
| --- | --- |
| 算法逻辑 | 优先查旧源码、旧引擎输入和原始输出，确认后对齐 |
| UI/工作流 | 在不违背新引擎语义时尽量保持熟悉体验 |
| 显示约定 | 可保留，但必须明确是显示层而非算法状态 |
| 已确认 bug | 不对齐；采用合理逻辑并记录差异 |

已确认示例：旧版 S-BGB 强制把第一个状态显示为 `/` 属于 bug，RASP5 不复刻；null range 按当前 BioGeoBEARS 模型实际状态空间处理。

## 4. 功能成熟度定义

| 等级 | 含义 | 发布处理 |
| --- | --- | --- |
| Stable candidate | 主链完整，已有真实计算和基本回归，等待 release gate | 默认显示 |
| Beta | 功能可用，但边界、数值或大数据验证不足 | 显示 Beta/说明 |

| Deferred | 有价值但不进入首个 RASP5 正式版本 | 不阻塞发布 |
| Removed | 实测后确认价值不足或设计有害 | 从代码、菜单和任务书删除 |

## 6. 已删除和明确延期的功能

### 6.1 Removed

以下功能不再进入路线图：

1. **Node Range Map / Range Map**：离散祖先 range 对粗颗粒 polygon 直接着色不能形成真正空间概率热图，信息增量不足，已删除。
2. **全树枝-时间多状态概率曲线场**：视觉拥挤、交互成本高、实际研究问题不明确，已删除相关实现，不再作为 RASP5 卖点。

### 6.2 Deferred

- 古地图、板块重建、GPlates；
- raster/environment overlay；
- posterior tree-set BSM 完整聚合；
- S-BayesTraits 贝叶斯树集合分析；
- 大型标准生物地理区数据库维护；
- Rust BioGeoBEARS 重写；
- 新的祖先分布统计模型。

延期不代表没有价值，而是不能继续阻塞首个可信 RASP5 版本。

## 7. 新工作包

### WP0：功能冻结与仓库基线

目标：把当前“能运行的开发现场”变成可追踪的基线。

任务：

1. 审核并提交 2026-07-12 审计时的 47 项 modified/untracked 文件，排除论文压缩包和运行产物。
2. 记录当前菜单、Stable/Beta/Experimental 功能清单。
3. 禁止在 RC 前增加新的顶层方法或高级地图模块。
4. 为当前内部引擎包和源码 checkpoint 建立一一对应关系。
5. 删除失效入口、重复 dialog、早期调试脚本和无效兼容分支。

完成标准：

- `git status` 干净；
- 源码 checkpoint 与引擎包有明确版本号；
- 从新 clone 可恢复当前开发版；
- 没有用户可见的死入口。

### WP1：核心方法数值可信度

目标：回答“这个按钮真正让哪个引擎用什么参数算了什么”。

任务：

1. 为每个稳定方法建立 `GUI -> config -> engine input -> raw output -> parsed result` 参数追踪表。
2. 建立 Psychotria 金标准：旧 RASP、原生引擎、RASP5 输入和输出均保存。
3. 固化 DIVA/S-DIVA、DEC/S-DEC、BGB/S-BGB、BGB model test、BBM 的回归容差。
4. 将 lagrange-ng evaluate d/e、period d/e、maxareas、period rules 加入自动测试。
5. 将 BayArea distancePowerPrior、initial rates、seed、多链和 burn-in 加入自动测试。
6. 统一节点/clade identity 审计，覆盖二叉树、拓扑差异、缺失 clade 和大树。
7. 明确所有 S 方法的有效树数、忽略原因和合并分母。

完成标准：

- 每个 Stable candidate 至少有一个原生引擎金标准；
- UI 中不存在“参数可编辑但运行不使用且不提示”的情况；
- 数值差异有来源、容差和说明，不用兜底代码强行逼近；
- S 方法报告 `input/effective/failed/unmatched tree count`。

### WP2：性状模块收口

目标：把“接入很多模型”改成“每种结果类型有正确解释”。

任务：

1. 将 BayesTraits 配置按模型和 ML/MCMC 动态显示相关参数。
2. 明确只有支持节点估计的路径进入祖先状态树图。
3. 将 Model A/B MCMC unknown-value、fastAnc、anc.Bayes、ace 的输出 schema 固化。
4. 将 log/log10 分析尺度、原始尺度展示、back-transform 和 CI 写入导出元数据。
5. 限制大树 BayesTraits Continuous ASR，并提供预计样本数/运行量提示。
6. 将 anc.ML BM/OU/EB 保持 Experimental，失败时输出诊断，不做静默 fallback。
7. 决定 publication A/B/C figure 和 DTT 是否进入首版；默认建议作为 Experimental export。

完成标准：

- 用户不会把模型参数误认为节点祖先值；
- 单/多性状和离散/连续列选择不会互相污染；
- 每个可视化都能追溯到明确的分析结果与尺度；

### WP3：空间数据工作流收口

目标：保证从原始记录到 range matrix 的过程可审计和可复现。

### WP7：论文证据和外部验证

目标：把软件功能转化为可审稿的科学证据。

建议论文主线：

> RASP5 provides an auditable desktop workflow from occurrence and range data to ancestral reconstruction and stochastic biogeographic event synthesis.

论文核心不应是“按钮更多”，而应是：

1. 旧版广泛使用工具的可信现代化；
2. 跨引擎统一但不篡改算法的工作流；
3. 从 occurrence/GeoJSON 到 range matrix 的可审计编码；
4. 从 BioGeoBEARS BSM 到事件时间和迁移网络的可重复综合；
5. 大树和真实大数据下的可用性与性能。

最低证据包：

- Figure 1：RASP5 架构与数据流；
- Figure 2：旧版/原生引擎/RASP5 数值一致性；
- Figure 3：树规模、区域数、tree-set、occurrence 数和 BSM map 数的性能；
- Figure 4：Dore 或同等级真实案例的端到端事件网络；
- Supplement：参数映射表、失败模式、完整 benchmark、版本和环境。

任务：

1. 至少 3 类固定数据：Psychotria、Primate、Dore。
2. 增加 5–10 个公开数据集，覆盖不同区域数、树规模和分布稀疏度。
3. 与旧 RASP、原生 BioGeoBEARS/lagrange-ng/phytools 等比较。
4. 报告准确性/一致性、成功率、运行时间、内存和可复现性。
5. 邀请 2–3 名未参与开发的用户按教程完成分析并记录失败点。
6. 明确 AI 辅助编码的披露方式和作者责任。

期刊定位：

- **首选现实目标**：MBE Resource 或 Methods in Ecology and Evolution Application/Research Article；
- **Nature Communications**：需要软件之外的重要生物学发现，不能只靠版本更新；
- **Nature Methods**：需要新的方法学/算法、系统仿真和广泛方法比较，当前主项目不满足；
- Systematic Biology、Ecography、Journal of Biogeography 可作为方法/应用故事匹配后的选择。

完成标准：

- 稿件每个主要结论都有固定脚本和数据支持；
- 软件版本与论文结果一一对应；
- 第三方可以从发布包复现主要图表。

## 10. 风险登记

| 风险 | 当前判断 | 处理 |
| --- | --- | --- |
| 外部引擎参数未真正进入计算 | 已在 lagrange-ng/BayArea 发现过 | 每个引擎建立参数追踪和最小诊断测试 |

| 继续扩功能导致旧功能回归 | 高风险 | M1 前功能冻结，每个 bug 必须带回归测试 |

## 12. RASP5 首个正式版本的完成定义

RASP5 v5.0 可以宣布完成，需要同时满足：

## 13. 本任务书的维护规则

1. 本文档是当前权威路线；旧任务书只保留历史决策。
2. 每次新增功能前必须标明它属于哪个工作包、成熟度和发布里程碑。
3. 解决 bug 后必须更新对应风险、测试或验证记录，而不只在聊天中说明。
4. 每个 checkpoint 更新“当前真实实现状态”，不把“有 UI”写成“算法已完成”。
5. Removed 功能除非出现新的明确研究需求，不得以换名字方式重新加入。
6. 论文目标不决定代码是否正确；正确性、可复现性和诚实边界始终优先。
